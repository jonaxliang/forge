# Forge 术语表

本文档定义 Forge 中文用户侧术语。中文界面、产品文案、帮助说明和面向用户的文档应优先使用这里的名称；代码、API、数据库表和 `.wf` 字段可以继续使用英文领域模型名。

## 命名原则

- 中文用户界面使用中文主称，避免中英文混用。
- `Forge`、`Agent`、`Skill`、`MCP` 保留英文。
- 用户侧只暴露必要概念，不把内部实现对象直接变成产品术语。
- 同一个对象只使用一个用户侧名称；如果需要解释英文名，只在技术文档中补充。

## 核心链路

用户侧主链路为：

```text
需求 -> 拆解结果 -> 任务 -> 任务工作流 -> 产物
```

- `需求` 是用户创建的目标描述。
- `拆解结果` 是需求拆解后的结构化结果，可编辑，但不是任务实体。
- `任务` 由用户确认拆解结果后生成。
- `任务工作流` 是任务执行过程和执行视图的统一名称。
- `产物` 是任务执行产生或收集的持久化结果。

## 核心对象

| 英文领域模型 | 用户侧名称 | 使用规则 |
| --- | --- | --- |
| Project | 项目 | 中文 UI 不使用 `Project`。 |
| Requirement | 需求 | 创建、拆解、验收的目标对象。 |
| Task Draft | 不使用 | 删除用户侧和目标系统概念，改用 `拆解结果`。 |
| Decomposition Result | 拆解结果 | 需求拆解后的结构化编辑对象。 |
| Task | 任务 | 从拆解结果生成，初始状态为 `初始化`。 |
| Task Board | 任务看板 | 任务管理主视图。 |
| Workflow Template | 工作流模板 | 只指任务执行用模板。 |
| Workflow File | 工作流模板 | 用户侧不叫工作流文件；导入时可说上传 `.wf` 文件。 |
| Workflow Run | 任务工作流 | 同时承载运行实例和运行视图。 |
| Workflow Run Control Room | 任务工作流 | 不单独暴露控制台概念。 |
| Cat Factory View | 不使用 | 删除，不使用猫工厂或流水线作为正式术语。 |
| Workflow Node | 节点 | 模板和任务工作流中都叫节点。 |
| Node Run | 节点执行 | 仅必要时使用，不作为主术语。 |
| Exit Criteria | 验收条件 | 用于节点或任务结果是否通过。 |
| Artifact | 产物 | 用户侧主术语。 |
| Artifact Version | 历史版本 | 不作为主术语，只在产物详情中使用。 |
| Skill | Skill | 保留英文，不翻译成能力或技能。 |
| Prompt | 提示词 | 用户侧不使用 `Prompt`。 |

## 需求状态

| 状态 | 含义 | 主要操作 |
| --- | --- | --- |
| 初始化 | 需求刚创建，尚未开始拆解。 | 编辑需求、拆解需求 |
| 拆解中 | Forge 正在生成拆解结果。 | 查看进度 |
| 拆解失败 | 拆解失败，没有可用拆解结果。 | 重新拆解、编辑需求 |
| 待生成任务 | 拆解结果已生成，等待用户编辑并生成任务。 | 编辑拆解结果、生成任务、重新拆解 |
| 已生成任务 | 已从拆解结果创建任务，任务可执行或已在执行。 | 查看任务、开始任务、验收需求 |
| 需求已完成 | 用户验收该需求下的产物并手动关闭需求。 | 查看产物、查看任务、重新打开需求 |

`需求已完成` 必须由用户手动标记，因为需求完成代表用户验收产物，不由任务状态自动推导。

## 拆解结果

`拆解结果` 是需求拆解完成后的结构化编辑内容。

- 不叫 `Task Draft`、`任务草稿` 或 `候选任务`。
- 不在用户侧暴露 JSON 编辑。
- 数据层可以用 JSON 保存。
- 用户侧只提供结构化编辑。
- 至少包含任务标题、任务描述和顺序。
- 支持新增、编辑、删除和排序。
- 用户点击 `生成任务` 后，才批量创建 `初始化` 状态的任务。

## 任务状态

| 状态 | 含义 | 主要操作 |
| --- | --- | --- |
| 初始化 | 任务已创建，但尚未开始执行。 | 编辑任务、删除任务、开始任务 |
| 执行中 | 最新任务工作流正在运行。 | 查看任务工作流 |
| 执行失败 | 最新任务工作流失败。 | 重新开始、查看失败原因 |
| 待验收 | 任务工作流已完成，等待用户验收产物。 | 查看产物、验收通过、要求返工 |
| 已完成 | 用户验收通过，任务关闭。 | 查看产物 |
| 已取消 | 用户取消该任务，不再执行。 | 查看记录、重新打开 |

工作流成功不等于任务完成。任务必须经过用户验收后才进入 `已完成`。

## 任务工作流状态

用户侧暴露最新一次任务工作流状态，并与任务状态保持同步。

| 任务工作流状态 | 对应任务状态 | 含义 |
| --- | --- | --- |
| 未开始 | 初始化 | 还没有启动任务工作流。 |
| 排队中 | 执行中 | 已请求执行，等待 Agent 接收。 |
| 运行中 | 执行中 | Agent 正在执行。 |
| 等待人工处理 | 执行中 | 需要用户补充信息、批准或处理阻塞。 |
| 执行失败 | 执行失败 | 本次任务工作流失败。 |
| 已完成 | 待验收 | 工作流执行完成，等待验收。 |
| 已取消 | 已取消 | 本次任务工作流被取消。 |

如果任务多次执行，主界面只展示最新一次任务工作流。历史执行作为系统记录保留，不进入核心术语。

## 工作流模板

`工作流模板` 只指任务执行模板，不包含需求拆解。

- 需求拆解是内置能力，不叫工作流模板。
- `Workflow Template` 和 `Workflow File` 在用户侧都叫 `工作流模板`。
- 导入按钮叫 `导入工作流模板`。
- 导入区域可以写 `上传 .wf 文件`。
- 模板详情中的源码区域叫 `模板源码`。
- 普通列表不强调 `.wf`。

## 节点

用户侧节点类型为：

| 节点类型 | 含义 |
| --- | --- |
| Skill 节点 | 调用 Forge 中定义的 Skill。 |
| MCP 节点 | 通过 MCP 服务调用 MCP 工具。 |
| 产物节点 | 生成、收集或整理产物。 |
| 人工节点 | 需要用户评审、审批、补充信息或验收。 |

不使用 `Agent 节点`。Agent 是执行资源，不是节点类型。节点可展示 `执行 Agent`，并可继承任务或模板配置。

## Agent 管理

| 内部或英文名称 | 用户侧名称 | 使用规则 |
| --- | --- | --- |
| Agent | Agent | 保留英文。 |
| Agent Binding | Agent 绑定 | 用于把 Agent 接入 Forge。 |
| Agent Connector | 连接方式 | 作为配置字段使用。 |
| Hosted Agent | Agent | 不单独暴露 Hosted Agent。 |
| Agent Pairing | Agent 协作 | 仅在真正支持多 Agent 协作时使用。 |
| Harness | 不使用 | 用户侧不出现。 |
| Bridge / Local Agent Bridge | 本地桥接 | 不使用 Bridge。 |

Agent 相关页面或设置区块叫 `Agent 管理`。当前版本不定义 `Agent 能力`、`能力上报`、`能力清单` 或 `Capability Registry`，这些概念未来如需支持，应放到专门配置区重新定义。

## MCP

- `MCP Server` 用户侧叫 `MCP 服务`。
- `MCP tool` 用户侧叫 `MCP 工具`。
- `MCP 节点` 只表示通过 MCP 服务调用 MCP 工具，不表示用 MCP 连接 Agent。
- 普通 UI 避免使用 `MCP Server` 和 `MCP 服务器`。

## 执行日志

任务工作流、节点和 Agent 执行过程中产生的可查看记录统一叫 `执行日志`。

- 任务工作流页签叫 `执行日志`。
- 节点详情区叫 `执行日志`。
- 原始输出也叫 `执行日志`。
- 不混用 `日志` 或 `执行记录`。

## 评审、审批、验收

| 术语 | 含义 |
| --- | --- |
| 评审 | Agent 或人对内容质量做判断。 |
| 审批 | 明确的人工放行决策，决定流程是否继续。 |
| 验收 | 用户确认任务或需求产物可以关闭。 |

不要把任务完成按钮叫 `审批通过`，也不要把节点质量检查叫 `验收`。

## 操作命名

| 场景 | 用户侧名称 |
| --- | --- |
| 创建需求 | 创建需求 |
| 拆解需求 | 拆解需求 |
| 拆解失败后再次拆解 | 重新拆解 |
| 从拆解结果创建任务 | 生成任务 |
| 启动单个任务 | 开始任务 |
| 启动多个任务 | 全部开始 |
| 重新启动任务执行 | 重新开始任务 |
| 节点失败后再次执行 | 重试节点 |
| 验收任务 | 验收通过 |
| 验收需求 | 验收需求 |

## 通用状态翻译

| 英文状态 | 用户侧名称 |
| --- | --- |
| idle | 未开始 |
| queued | 排队中 |
| running | 运行中 |
| waiting | 等待中 |
| blocked | 已阻塞 |
| reviewing | 评审中 |
| failed | 失败 |
| succeeded | 成功 |
| skipped | 已跳过 |

## 设置

| 英文或内部名称 | 用户侧名称 |
| --- | --- |
| Settings | 设置 |
| Project settings | 项目设置 |
| Default | 默认值 |
| Model settings | 模型配置 |
| Artifact Storage Mode | 产物存储方式 |
| Database strategy | 数据库类型 |
| local-only | 仅本地 |
| cloud | 云端存储 |

模型配置区块不叫 `拆解模型`、`规划模型` 或 `Planner`。如需说明用途，可写 `用于拆解需求`。

## 避免使用

中文用户侧应避免以下术语：

- `Task Draft`、`任务草稿`、`候选任务`
- `Workflow Run Control Room`、`Control Room`、`工作流运行控制台`
- `Cat Factory View`、`猫工厂`、`流水线`
- `Workflow File`、`工作流文件`
- `Harness`、`执行平面`、`Agent 中控`
- `Bridge`、`Agent 代理`
- `Agent Connector`、`Hosted Agent`
- `Agent 能力`、`能力上报`、`能力清单`
- `Agent 节点`
- `Prompt`
- `准出条件`、`退出条件`、`完成条件`
- `日志`、`执行记录`

其中日志统一叫 `执行日志`。
